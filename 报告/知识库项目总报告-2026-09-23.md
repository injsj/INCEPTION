## 一、项目与设计评价

这是一个"人控知识库 + 符号 AI"系统，核心设计决策经得住审查：

| 设计 | 评价 |
|------|------|
| AI 只能提申请、落库必过人工裁决 | 提示注入的最坏结果只是"提交一条垃圾申请"，成立 |
| 密钥只存 SHA-256 哈希、只显示一次 | 密钥为高熵随机串，无加盐可接受 |
| 信任生命周期四分区（信任/存疑/待审核/申请） | 自洽，授权随分区自动生效/失效 |
| 哈希链审计日志 | 防"不懂 logstate 的篡改者"，单机场景够用（天花板见第六节） |
| 思想自由、行动受控（白名单执行器） | 推演输出与执行许可分离，正确 |
| 序号只增不减 | 保证日志/授权永远指对东西，但要求所有调用方不假设具体编号（本轮修了 selftest 在这上面的缺陷） |

## 三、第二轮审查新发现与修复（2026-09-23，22 项）

### 高危（3）

1. **存储层并发裸奔**——日志锁只护住了 logstate，counters/index/keys/applications 的读-改-写全无锁；FastAPI 线程池并发或 CLI 跨进程并发会产生重复标记 ID。→ 新增 `safeio.meta_lock`（进程内 + 跨进程、可重入），17 个写函数统一串行化。验证：8 线程 × 5 并发录入 40 个 ID 全唯一。
2. **请求体 1MB 上限可被 chunked 编码绕过**——对外开启时是远程内存 DoS 口。→ chunked 请求流式累计字节超限即 413，正常请求不受影响（专项测试中抓到首版实现的 422 回归并修正）。
3. **匿名日志注入破坏审计**——申请自报名称含换行符即可注入伪造日志行，哈希链校验永久报断裂。→ 入链内容统一压单行。验证：注入后日志净增 1 行、链完好。

### 中危（6）

4. 申请状态机无守卫（已执行的 REQ 可被覆盖为已拒绝）→ 裁决入口内建状态守卫。
5. AI 会话状态非原子写（崩溃丢全部提醒）→ session/队列/对账/链头等 6 处全部原子写。
6. 历史备份秒级文件名同秒覆盖 → 毫秒精度。
7. 临时授权时长无边界（0/负数/超大值/非数字 500）→ 钳制 1~720 小时、非法 400。
8. 频率训练稀释安全告警权重（违背"安全最高优先"）→ 安全类永不自动降权。
9. 推演同值结论置信不升级 → 高置信路径可升级并留痕"置信升级"。

### 低危（10）

10. 追问缺槽无退出 → 取消词 + 5 轮超时。11. 急诊预筛吞掉未到期提醒 → 提醒只发建议不结案。12. 档案同毫秒覆盖/目录膨胀 → 月度子目录 + 碰撞序号。13. aging 死 id 膨胀 → 保存时清理；截断优先保未完成事件。14. 非 Windows 导入即崩 → windll 守卫降级。15. 索引路径越界 → entry_path 目录约束校验。16. admin.html 类型名未转义 → 统一转义。17. 批准申请先改状态后建密钥 → 调换顺序 + 冲突回收。18. brain 落盘频次 → 评估可接受不改。19. 清理项 → 本轮已执行（见下）。

## 七、新增功能：原子操作清单（变更 #11，2026-09-23）

变更 #6 诚实清单的第一项（也是最实质性的遗留项）落地：

## 八、第三轮审查新发现与修复（2026-09-23，8 项修复 + 2 项记录不改）

第三轮覆盖前两轮未细读的模块（dlgact / langid / toy / 管理菜单 / ai_client）并复查第二轮自改代码（meta_lock 锁序、chunked、predict/atoms 接入点）——复查无回归性缺陷。新发现 1 中危 + 4 低危 + 5 信息级，其中 8 项全部修复（明细见《cangku第三轮审查报告-2026-09-23.md》）：

### 中危（1）

1. **"密钥缺失不致命"的承诺失效（实测复现）**——`kb.get_client` 内部 `load_api_key` 抛 SystemExit，`except Exception` 捕不到，`Session(api_key=None)`、`toy.run`、无密钥查库三条路径直接退出进程（当前因 `state/ai_key.txt` 存在而是潜伏炸弹）。→ `get_client` 捕获 SystemExit 返回 None；session / toy / refine 三处判空走断连降级文案（规格 #16：本地任务照常），`submit_req` 未提交时建议保持待裁决可重试。

### 低危（4）

2. **终端转义注入**——匿名访问申请的自报名字/理由可含 ANSI 控制符，管理菜单原样打印（可清屏、伪装提示；网页端有 esc() 不受影响）。→ 入库前剥离 C0 控制字符与 DEL（保留 \t\n\r，杀死 ESC 即杀死全部 ANSI 序列）。
3. **落盘权重无校验**——手改 session.json 可注入任意权重（如安全告警=0），绕过训练层 ±20% 约束。→ `state.load()` 逐键校验：只认种子表类型、拒布尔与非数值、按种子值 ±20% 钳制（与 `adjust_weight` 同一把尺子）。
4. **wait() 傻等 401**——`ai_client.wait()` 把 401/403 也当临时故障重试一小时才报超时，AI 学不到"身份不被承认"这个最重要的信号。→ 401/403 立即抛出；连接失败(-1)照旧重试、耗尽报 408。
5. **已处理申请无限膨胀**——applications.json 只增不减。→ 已处理条目只留最近 500 条（待审全留）；修剪原地过滤保持"列表尾部=最新"不变量（首版重排实现被回归测试抓出并修正——这本身就是测试价值的实证）。

### 信息级顺手修（3）

6. `atoms.safe_eval` 排除布尔字面量（bool 是 int 子类，"计算 True" 曾等于 1）。
7. `timenorm` 支持「点半」（=30 分）与「晚上12点 / 今晚12点半」（口语午夜=次日 0 点，此前报"时段与钟点对不上"）。
