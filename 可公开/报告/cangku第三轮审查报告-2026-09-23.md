## 一、中危

### R3-1. "密钥缺失不致命"的承诺失效：AI 会话启动即崩溃（已实测复现）

**位置**：`AI/brain/session.py` `Session.__init__`、`AI/brain/toy.py` `run()`

**问题**：`session.py` main() 的注释和降级文案都承诺"未配置密钥仍可聊天，知识库功能将提示断连"。但：
- `Session.__init__` 调用 `ruleload.load_rules(self._kb())` → `kb.get_client(None)` → `config.load_api_key()` 抛 **SystemExit**——`except Exception` 捕不到它（SystemExit 不是 Exception 的子类），进程直接退出；
- `toy.py` 查库路径同样裸调 `kb.get_client(api_key)`。

实测：临时指向不存在的密钥文件后，`Session(api_key=None)` 与 `toy.run("查一下P1")` 均崩溃。当前 `state/ai_key.txt` 存在所以是**潜伏炸弹**——换机器、误删文件、或按说明书只配了环境变量的场景立刻触发。

**方案**：`Session.__init__` 的规则加载兜底改为 `except (Exception, SystemExit)`；`kb.get_client` 设计改为"返回可用客户端或 None"，调用方按断连降级处理（与规格 #16 语义一致）。

## 三、信息级（记录在案，非必须修）

1. `timenorm` 不支持口语"晚上12点"（午夜 0 点）与"12点半"（=30 分）——语言层天花板，用户会被反问兜底，无故障。
2. `atoms.safe_eval` 接受 `True/False` 字面量（bool 是 int 子类）："计算 True" 返回 True——无害但诡异，可一行排除。
3. `discovery.mine_shortcuts` 合并候选规则时不查条件矛盾（可能产出"饥饿=极高 且 饥饿=高"式候选）——有人审兜底，记录。
4. `meta_lock` 等锁上限约 10 秒，超时抛 OSError → 高竞争下 API 偶发 500——概率低，可接受。
5. `atomic_ops.jsonl` 崩溃时最多损坏末行，矿工已跳过坏行——设计可接受。
