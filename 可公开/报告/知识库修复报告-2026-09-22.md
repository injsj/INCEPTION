## 二、逐项明细（原因 → 方式 → 结果）

### 1. 管理网页开关"一键三连"（高）

- **原因**：管理网页 `toggle()` 每次只提交被点的那个开关（如 `{"catalog_public": false}`），但 `admin_api.set_state` 把三个键（缺省值为 `None`）全部透传给 `store.set_state`；store 层 `if k in kw` 恒真、`bool(None) = False`，于是**没点的开关被静默改成"关"**。最糟情况：在网页点"目录公开"或"对外访问"，`enabled` 被置 False → 一切 HTTP 访问（含管理页本身）立即 503，只能用 CLI 恢复。
- **方式**（双保险）：
  - `kb/admin_api.py`：只转发请求体中实际出现的键（`{k: body[k] for k in (...) if k in body}`）；
  - `kb/store.py`：`set_state` 增加 `kw[k] is not None` 判断，None 一律视为"未指定"跳过。
- **结果**：专项测试——单键更新后另外两个开关保持原值 ✓；故意透传 None 不再改写任何开关 ✓。

### 2. selftest 不可重复运行（高）

- **原因**：正式密钥只在首次创建时显示一次明文（服务端只存哈希）。自检直接用正式密钥做 HTTP 测试，重跑时 `add_key` 返回 None → 所有带密钥的请求 401。实测修复前重跑：**21 通过 / 6 失败**（AI 读取、AI 提交申请、管理端点等全灭）。
- **方式**：重写密钥准备段——正式密钥只确保存在；HTTP 测试改用**每次现建现销的自检临时密钥**（自检管理员/自检AI/自检访问员），结尾吊销，开头也会先清上次异常残留；访问方断言不再因"密钥取不回"而跳过；自检产生的访问申请当场标记"已拒绝（自检自动清理）"，不再每跑一次堆一条待审。
- **结果**：用项目自己的 .venv **连续运行两次，均为 28/28 全部通过**（此前跳过的"申请可标记已执行"也恢复执行，故总数回到说明书所说的 28 项）；运行后密钥列表无任何"自检*"残留 ✓。

### 3. requirements.txt 缺 requests（高）

- **原因**：`selftest.py` 依赖 requests，但依赖清单只有 fastapi/uvicorn；项目 .venv 实测未装 requests → 按说明书跑 `python selftest.py` 直接 `ModuleNotFoundError`。
- **方式**：requirements.txt 增加 `requests>=2.31`（注释标明仅自检使用）；并已把 requests 2.34.2 实际安装进 `D:\cangku\.venv`。
- **结果**：.venv 下 `import requests` OK，自检直接可跑 ✓。

### 4. 回滚分区不一致（中）

- **原因**：`store.rollback` 把历史文件原样写回当前位置，条目 JSON 里的 `zone` 仍是备份时刻的旧值。若条目在备份后移过区，回滚后"条目 zone"与"索引 zone"不一致——授权判断（读条目 zone）与目录/索引（读 index zone）各说各话，可能出现信任区条目被按待审核区拒读。另外条目已被废弃时回滚会对着 None 路径写文件（TypeError）。
- **方式**：回滚前先查索引：条目不存在返回明确错误；写回前强制 `entry["zone"] = 索引当前分区`。
- **结果**：专项测试——在待审核区建条目 → 移信任区 → 回滚到移区前版本：修复前会得到"条目 pending / 索引 trusted"，实测修复后两边均为 trusted 一致 ✓（验证条目已废弃清理）。

### 5. 审计日志跨进程竞争（中）

- **原因**：说明书明确支持"服务运行时同时使用管理菜单"，但哈希链的 `logstate.json` 是读-改-写且只有进程内锁。两个进程同时写日志会各自读到同一前哈希 → 文件里出现两行引用同一前哈希 → 校验误报"断裂"。
- **方式**：`kb/audit.py` 增加 Windows 跨进程文件锁（`msvcrt.locking`，锁定 `logs/.xlock` 第 0 字节，最多等待约 10 秒；非 Windows 自动退化为进程内锁），把"读 logstate → 追加日志行 → 写 logstate"整体置于锁内。
- **结果**：自检（服务端+主线程高频写日志）两条哈希链校验均完好 ✓。

### 6. CLI 健壮性两处（低）

- **原因**：① `m_applications` 批准前不复查申请状态，已拒绝的申请还能再批准并发密钥；申请编号不存在时 `get_application(n)["ids"]` 抛 TypeError（被菜单兜底成"操作出错"）。② 存疑→信任时输入的经验确认编号无越界检查，越界编号静默无效。
- **方式**：批准前统一校验"申请存在且状态为待审"；经验编号越界时打印"忽略越界编号 N"。
- **结果**：编译通过；自检全绿（CLI 改动不影响 HTTP 路径）✓。

### 7. 限流表内存膨胀（低）

- **原因**：`ratelimit._hits` 为每个新 IP 建队列且永不删除，对外开启后长期运行会缓慢涨内存。
- **方式**：表超过 10000 个 IP 时惰性清理沉寂项（窗口内无请求的整条移除）。
- **结果**：编译通过；自检的限流相关行为不受影响 ✓。

### 8. langid 误判（低）

- **原因**：`langid.detect` 取"第一个字母"定语言，`P1讲了什么` 首字符是拉丁字母 P → 误判 en，与整句是中文的事实不符。
- **方式**：扫描全句，命中任何特征文字（汉字/假名/谚文/西里尔/阿拉伯）即返回该语言；拉丁字母降级为兜底。
- **结果**：`P1讲了什么 → zh`、`查一下P1 → zh`、`hello world → en`、`你好 → zh` ✓。
