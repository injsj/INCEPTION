# 知识库服务 · 使用说明与注意事项（先读我）

> 本文件在 `D:\cangku` 根目录，知识库程序在 `D:\cangku\知识库\`，AI 本体在 `D:\cangku\AI\`，历次审查报告在 `D:\cangku\报告\`。
> 建议按顺序阅读：①快速开始 → ②日常使用 → ③注意事项 → ④出问题怎么办。

## 一、这是什么

一个用 Python 写的、给 AI 准备的知识库服务，PyCharm 直接可用。
所有录入都是**普通中英文打字**，程序自动转成 JSON 结构并分配标记（如 P1、L2）。

四种身份：

| 身份 | 谁 | 能做什么 |
|---|---|---|
| 管理员（固定名称 admin） | 你 | 开关服务、录入知识、审批、执行 AI 的申请、授权/踢人、看日志 |
| AI（固定名称 AI助手） | 你设计的 AI | 自由调用全部四个区的知识做研究；**不能写库**，改任何东西都要提交申请 |
| 人类访问方 | 你批准的人 | 只能按标记只读自己被授权的知识 |
| 匿名者 | 任何人 | 只看目录（简介）、提交申请 |

## 二、快速开始（PyCharm 一键运行）

整个程序就是 `D:\cangku` 这一个文件夹，**只需要运行一个文件**：

1. 打开 PyCharm → `File` → `Open` → 选择 `D:\cangku` → `Trust Project`（信任项目）
2. 在左侧文件列表找到 **`启动服务.py`** → 右键 → `Run '启动服务'`（运行）
3. 第一次运行时它会自动装依赖（需联网，几分钟，以后不再出现），并生成密钥

启动后看 PyCharm 下方控制台（Run 窗口）打印的地址：

- **目录界面**（给访问方/AI 看简介、提交申请）：`http://127.0.0.1:8320/static/catalog.html`
- **管理界面**（仅本机，用管理员密钥登录）：`http://127.0.0.1:8320/static/admin.html`

日常管理用另一个文件：右键 **`管理菜单.py`** → 运行，出现中文菜单
（开关、录入、审批、授权、处理 AI 申请、日志都在里面，服务运行时也能用）。

> PyCharm 第一次运行如果提示选择解释器（Interpreter），选一个 Python 3.10 或更高版本即可；
> 没有的话先装 Python（安装时勾选 Add to PATH）。

**第一次启动生成的两个密钥（管理员、AI）只显示一次，请立即复制存到安全的地方。丢了只能重建（重建后旧密钥全部作废，要重新发给 AI 和访问方）。**

## 三、日常使用流程

### 第 1 步：建类型（菜单选 4）
给每类知识起个名 + 指定一个开头字母，例如 `python` → `P`，`linux` → `L`。
字母全局唯一、只能加不能改。**没有类型就无法录入知识。**

### 第 2 步：录入知识（菜单选 5）
直接打字即可，五个要素是强制的：
- 标题、简介（这两样会出现在公开目录里）
- 详细使用方法、详细使用经验、局限性（受保护，只有被授权的人能看）

新知识默认进**待审核区**。

### 第 3 步：审核与移区（菜单选 8）
审核通过的知识移到信任区；能用但原理不明的移到存疑区。
**存疑区→信任区**时，系统会让你确认哪些经验被证实了（confirmed）、哪些被证伪（disproven）。

### 第 4 步：给别人/AI 授权
- 对方打开目录页，勾选想要的条目、填理由提交申请。
- 你收到申请后（菜单 11，或管理网页）批准，并**给对方指定一个固定名称**（不能和别人重复，不能叫 admin / AI助手）。
- 系统生成对方专属密钥，**只显示一次**，复制下来私下发给他（微信/邮箱等）。
- AI 不走申请：把 AI 密钥直接配置到你的 AI 程序里（接口见 README.md 或下方"AI 接口"）。

### 第 5 步：日常管理
- **追加/收回授权**（菜单 12）：可随时给某人多授权一个标记，或收回某一个、或一键吊销踢出——≤1 秒生效。
- **临时授权**（菜单 12-3）：访问方需要验证某条待审核区知识时，给他几小时的临时调用权，到期自动失效。
- **处理 AI 的申请**（菜单 13）：AI 想修改知识/新增知识/追加经验/移区/把存疑知识打回待审核，都会出现在这里，每条都附带了它的理由和证明过程。你逐条审阅，确认后系统让你亲手执行（复杂修改建议用菜单逐字段确认）。
- **看日志**（菜单 14）：谁调用了什么、什么时候、成功还是越权；你做了什么管理操作，分开记录且带哈希链防篡改。
- **后悔药**（菜单 15）：任何知识被修改前自动备份旧版本，可回滚到任意历史版本。

## 四、给 AI 的接口（配置到你的 AI 程序里）

**最省事的方式：直接让 AI import `zhishiku\ai_client.py`**（纯标准库、零依赖），
它封装了浏览目录、读取知识、提交申请、轮询进度，错误码带语义（403=无权限、404=标记不存在、503=服务关闭）。
文件头部有完整注释说明每个反馈信号对 AI 的含义。下面的原始 HTTP 接口供参考：

```bash
# 调用知识：AI 可读全部区（含待审核区，用于研究）
curl -H "X-API-Key: <AI密钥>" http://127.0.0.1:8320/api/kb/P1

# 提交修改申请：五种动作，理由(reason)和证明过程(proof)必填，缺一拒收
curl -X POST -H "X-API-Key: <AI密钥>" -H "Content-Type: application/json" -d '{
  "action": "modify",
  "target": "P1",
  "proposal": "建议补充的修改内容",
  "reason": "为什么需要这个修改",
  "proof": "验证步骤、测试数据、推理链"
}' http://127.0.0.1:8320/api/req

# action 可选：modify(修改) / new(新增) / append_experience(追加经验) / move_zone(建议移区) / suspect_to_pending(存疑转待审核)

# 查询申请进度（状态：待审核/已执行/已拒绝 + 管理员意见）
curl -H "X-API-Key: <AI密钥>" http://127.0.0.1:8320/api/req
```

**重要设计**：AI 即使被提示注入攻击、行为异常，也**无法直接改动知识库**——它只有"提申请"的能力，实际落库的每一步都过你的手。

## 五、注意事项（务必阅读）

### 密钥安全
1. 三个密钥（管理员、AI、各访问方）**只显示一次**，立即保存。服务端只存哈希，连管理员自己也找不回明文。
2. 密钥 = 身份。泄露了谁的就等于变成谁。怀疑泄露 → 菜单 12-4 立即吊销重建。
3. 访问方密钥只能读、不能改，即使泄露最坏情况也只是看了几条知识。

### 网络与对外访问
4. 默认**仅本机**可访问，网络上找不到这个服务。
5. 要给别人用时：菜单 2 打开"对外访问"，**重启服务后生效**（绑定地址在启动时决定）。
6. 对外开启后管理端点仍然只有本机能进（代码层硬隔离），但**密钥走明文 HTTP**，建议只在可信家庭/办公局域网使用；不可信网络请在 `kb/config.py` 配置 HTTPS_CERT 启用 HTTPS，或让外部人员用 SSH 隧道访问你的 127.0.0.1。
7. 对外开启期间，匿名目录和申请接口有每 IP 每分钟 60 次限流和申请队列上限（100 条），防止刷爆。

### 总开关
8. 菜单 1 关闭总开关后，**一切 HTTP 访问立即返回 503**（目录、调用、AI 全部断开）。重新打开也是 ≤1 秒生效。开关关闭期间本 CLI 照常可用（这是逃生通道，不会出现"关了谁也打不开"的死锁）。
9. `/health` 不受总开关影响（仅本机可见），用来确认服务进程还活着。

### 数据与备份
10. 所有数据都是磁盘上的普通文件，**直接备份 `data/` 和 `meta/` 两个文件夹**就是完整备份。四个区物理隔离，也可按区单独备份。
11. 你可以在 PyCharm 里直接打开 `data/` 下的 JSON 修改——服务 30 秒内会侦测到并在 admin 日志记一条"外部修改"（但不会记录操作者和具体内容，完整审计请走管理端）。
12. **不要随意手工编辑 `meta/` 下的文件**（state.json、keys.json、index.json 等），改坏了服务可能异常。改坏了就跑 `python admin_cli.py` → 菜单 16 自检，或删掉 meta/index.json 后重启（索引会自动重建）。
13. 知识标记序号只增不减：删掉 P2 后下一条仍是 P3，不会重用 P2（保证日志和授权记录永远指对东西）。

### 服务运行
14. 单进程运行足够（这个量级每秒几千次调用无压力）。PyCharm 调试时别开 reload 多进程。
15. 端口默认 8320，被占用就改 `kb/config.py` 里的 PORT。
16. 日志文件持续增长，长期运行可定期把 `logs/` 两个 .log 文件剪切归档（哈希链只保证单文件内连续，归档时按天分开存即可）。

### 演示数据清理
17. 自带的演示内容：类型 python/linux，信任区、存疑区、待审核区各一条演示知识（标记编号不固定——序号只增不减，废弃后重建会分配新号，如 P5/P6/P7）。自检产生的申请与临时密钥会当场自动清理，不堆积。清理演示知识：菜单 9 废弃这三条。**不要直接删文件**，走菜单才会正确更新索引和日志。

### 自检
18. 任何时候都可以跑 `python selftest.py`：28 项端到端检查会重新验证整个系统，且**可重复运行**——自检使用每次现建现销的临时密钥（自检管理员/自检AI/自检访问员），不碰只显示一次的正式密钥；仍会写入少量演示数据（见上条）。

## 六、出问题怎么办

| 现象 | 处理 |
|---|---|
| 页面打不开 | 服务没启动：`python -m kb.main`；端口被占用改 config.py |
| 提示"服务已被管理员关闭" | 总开关被关了，菜单 1 打开 |
| 访问方说密钥突然失效 | 被吊销/收回/临时授权到期，菜单 12 查并重新授权 |
| AI 说提交申请失败 | 看它有没有带齐 reason + proof；动作类型是否五种之一 |
| 忘记了管理员密钥 | 无法找回（只存哈希）。用 CLI 菜单 12-5 之外的办法：删除 meta/keys.json 后重新 init（**所有密钥作废需重建转交**） |
| 怀疑日志被改 | 菜单 14 或网页里"校验哈希链"，能定位到被改的行 |
| 误修改了知识 | 菜单 15 回滚到历史版本 |
| 服务行为异常 | 菜单 16 自检；重启服务；仍不行就备份 data/ 后重建 meta/ |

## 八、设计变更记录（改了主意就记在这里）

> 这份记录的作用是：防止未来的自己忘记"当初为什么改成现在这样"。每次对模型结构做大的改动，都在下面补一条。

### 变更 #1（2026-09-20）：两区模型 → 合并模型

- **原设计**：分成两部分——存储区只放知识本体；知识库只放每条知识的用法和经验。AI 先查知识库（用法经验层），再决定去存储区调用哪些知识正文。
- **变更为**：合并为一个条目（标记 + 五要素 + 正文），用四个分区（信任/存疑/待审核/申请区）承载知识的信任生命周期。
- **原因**：两区模型需要两套授权、两套 ID、两套生命周期，对"一个 AI + 少数访问方"的规模是纯负担；合并后"先看简介再决定调用"的流程由目录页 + 按标记授权完整保留。
- **代价**：用法/经验不再能跨知识复用（但存疑区设计要求经验带证明链跟随知识，与此一致）。
- **遗留**：原设计中"AI 的决策只面向轻量元数据"的思想以目录接口（/api/catalog）的形式保留了下来。

### 变更 #2（2026-09-22）：AI 本体设计定稿并开工

- **内容**：AI 施工依据落成 `AI\AI规格书.md`（两栏对照式：设计原话 → 工程落地）；工程骨架 `AI\brain\` 建立；第一站完成——玩具句端到端（语言识别→分词→多候选解析打分→白名单执行→知识库调用→回答→档案留痕）实测通过。
- **关键设计决策（含多轮审查的补丁）**：思考机制修正为"一切皆可入算，注意力决定每次谁入算"（框架问题的工程解）；生物推演以概率为主（三档定性概率：高/中/低）；思想自由、行动受控（推演不设闸，执行过白名单）；裁决者为可替换接口（本期人类实现，预留自动化与奖励机制插槽）；神经网络外挂三档（现成LLM→轻量分类器→本地模型）；内存/显存上限默认 50% 可调。
- **审查记录**：注意力机制 3 漏洞、思考机制 3 致命 4 重要、全链路 20 漏洞，全部有解决方案并入册。

### 变更 #3（2026-09-22）：工程修复（不改设计，只修实现）

- **管理网页开关修复**：`/admin/api/state` 只下发请求体里实际出现的开关键，`store.set_state` 跳过 None——修复"网页上拨任一开关会把其余两个静默关掉（含误关总开关导致全站 503）"。
- **selftest 可重复运行**：改用每次现建现销的自检临时密钥，不再依赖只显示一次的正式密钥明文（此前重跑必败 6 项）；自检申请当场清理；requirements.txt 补 requests。
- **回滚分区一致性**：rollback 以索引当前分区为准覆写条目 zone，避免带回备份时刻的旧分区导致授权与目录各说各话。
- **审计日志跨进程互斥**：logstate 读-改-写加 Windows 文件锁（logs/.xlock），服务与 CLI 并发写日志不再产生伪"断裂"。
- **小修**：CLI 批准申请前复查状态、存疑→信任经验编号越界提示、限流表惰性清理防内存膨胀、langid 修复"P1讲了什么"类句子误判为英语。

### 变更 #4（2026-09-22）：第二站骨架版完工（AI 获得第一个真实能力）

- **内容**：`AI\brain\` 新增七个模块（timenorm/dlgact/events/attention/stats/state/resources/session），intent.py 加提醒模板。AI 从"处理玩具句"升级为"能进行简单真实对话"：可登记提醒、缺槽会反问、用户补料能回填；煤气等急诊关键词命中立即给安全建议（仅建议，无执行器）；知识库没启动时本地功能照常、库相关请求提示断连。
- **注意力调度按规格 §3 落地**：类型权重（慢变量，种子值 安全告警2.0/提醒1.2/知识查询1.0/闲聊0.6，明文可查）决定先看谁；事件紧急分（严重度+截止紧迫度，与类型无关）决定执行序；三保险=急诊预筛/等待老化（+0.1每轮，封顶+0.5）/紧急打断；每轮预算 K=3。
- **留痕**：每次类型权重变化记 `state\weights.log`（哈希链，可验伪）；每轮全状态落盘 `state\session.json`（崩溃恢复）；每轮档案 `archive\task_*.json`。
- **内存上限**：默认只用一半内存，超了自动降速；比例可调（写 `state\resource_cap.json`，如 {"mem_cap": 0.5}）。
- **运行方式**：`cd AI` 后 `python -m brain.session`（交互）或 `python -m brain.session --script "句子"...`（脚本+状态速览）。
- **实测记录**：断连场景5句、在线场景（404路径、目录检索、权重调节留痕）全部通过；修复3个施工bug（json导入、急诊重复触发、调节不落盘）。

### 变更 #5（2026-09-22）：第三站·训练层与建议队列

### 变更 #17（2026-09-24 凌晨起，三批连贯施工）：推理环接入主路——先分析、再试解、不行再说不懂

- **起因**（设计者原话定调）：「我要的是真正的逻辑思考……而不是搜索，这是搜索引擎」「只要经验足够，它就会动用自己的一切知识作为工具来攻坚，直到耗尽方法」。此前的 unknown 路径是「认不出就检索，检索不到就说不懂」——那是搜索引擎，不是推理。
- **攻坚顺序**（AI/brain/session.py _do_unknown 重排）：① 拆得开就拆（多子句逐个解决，任一解不了就整句退回原流程，不硬拆）→ ②「需要什么/怎样才能」式问题走反问桥反向推演 → ③ 普通问句走问答桥：认出事实→规则链正向推演→带置信作答；条件不足→诚实列出还缺什么（观察是合法动作）→ ④ 推演无解才轮到知识库检索 → ⑤ 全落空→讲清试过什么再说不行。
- **问答桥**（AI/brain/reason.py answer_question）：从句中认事实（短语模式+规则值词匹配，GENERIC_VALUES 防「充足睡眠」误触发「光照=充足」），正向传播后按与问题的相关性筛结论（变量名与问句公共子串≥2），链生结论随链保留，被滤掉的在思考链里报数。
- **反问桥**（answer_need）：锁定目标变量→backward 反向找路径；先认句中事实，已满足的条件不再列为「还缺」，条件齐全的路径直接 forward 给结论。**极性分流**：规则结论是目标反面（熄灭/不会/失败……）时不冒充「达成路径」，改作逆否使用——「要达成 X 就不能让这套条件凑齐，拆掉任意一条即可」，并指出哪些条件已成立、关键别让哪条出现；阻止类意图（防止/避免/怎么才能不）正负互换。只有逆否路径时补一次知识库检索，条目正文往往就有答案。
- **人话思考链**：task["thinking"] 全程记录「先分析这是什么→再试哪条路→走不通就换」，聊天页 trace 面板置顶渲染为编号时间线（inception.html .tstep/.tno/.ttext）。
