## 运行（第二站骨架版）

```bash
cd D:\cangku\AI
# 密钥二选一：环境变量，或写入机密目录（2026-09-27 变更 #33：移出仓库树）
set KB_API_KEY=<AI密钥>
:: 或不设环境变量：把密钥写入 D:\机密\ai_key.txt（可用 CANGKU_SECRET_DIR 改址）

# 交互模式（输入「退出」结束）
python -m brain.session

# 脚本模式（跑完自动 dump 状态：事件/权重/统计/weights.log 尾部）

```

前提：`zhishiku` 知识库服务已启动（运行上级目录的 `启动服务.py`）。
没启动也能聊：知识库相关请求会提示断连，提醒/闲聊等本地功能照常（规格 #16 优雅降级）。

## 推演层用法

```bash
cd D:\cangku\AI
python -m brain.reason                 # 完整演示（野兽示例 + 逻辑域 + 对账）
python -m brain.reason 饥饿极高 无捍卫亲友意念 友人在场   # 单句推演
# 会话里直接说：推演 受力平衡  也能触发
```

种子规则在 reason.py 的 SEED_RULES 里明文列着（谁填的、依据是什么都写了）。
要加规则直接往列表里加一条：
{"id": "R8", "when": ["变量=值"], "then": "变量=值",
 "tier": "高/中/低", "domain": "生物/物理/...", "source": "出处"}

**经验提炼（变更 #8，低配版先用着）**：矿工每 10 轮翻一次档案（变更 #8）：
- 共现：两条规则常一起触发 → 可能有共同上游
- 捷径：规则链反复出现 → 候选直达规则（新知识的雏形，附证据）
- 趋同：多条规则指向同一变量 → 可能是同一现象的不同描述
候选出现在 `python -m brain.refine` 里，你 `--req` 批准后作为新知识 REQ 入库终审。
数值趋同（如 3×3=3+3+3 式发现）需要算术留痕，等原子操作清单上线后补。

**规则已入库（变更 #7）**：知识库新增类型「推演规则」（标记 G1-G7，存疑区），会话启动
自动从库里加载 G 类规则执行，断连时用上面种子规则兜底（输出里的规则编号 R1/G1 可区分
来源）。对账自动计数（state\rule_reconcile.json），命中≥3 且命中率≥70% 会出现在建议
队列（`python -m brain.refine`），你批准 `--req` 后发移区 REQ，批准后规则升信任区。

## 建议队列用法（你是裁决者）

```bash
cd D:\cangku\AI
python -m brain.refine              # 查看待裁决建议
python -m brain.refine --apply S1   # 批准词典类（写入 lexicon_extra，立即生效）
python -m brain.refine --req S2     # 批准知识缺口类（提交 REQ 到知识库，管理菜单里再裁决）
python -m brain.refine --drop S3    # 拒绝
```
