## 1. 语言层

| 设计原话 | 工程落地 |
|---|---|
| 【原话】先调用知识库识别语言类型 | **字符集规则**，零成本：汉字→zh，假名→ja，谚文→ko，西里尔→ru，阿拉伯→ar，拉丁→en（默认）。知识库不为此被调用 |
| 【原话】拆到"再拆就语法不完整"的最小单位 | 停止线 = **每个成分都能在词典查到释义**（词典=知识库词条 + AI 本地种子词典） |
| 【原话】拆句→解析→放回字词→再解析，重复至完整 | 实现为**模板+规则的句法分析**，语法规则做**剪枝器**（不合法结构不展开，防指数爆炸）；候选解析保留 top-k=5 |
| 【原话】拆不开就不拆（尽力而为） | 解析失败降级为"关键词+语义槽"粗解析，并记录失败案例（将来走 REQ 申请新规则） |
| 【原话】强大的语言能力做地基 | v1 接受天花板现实：语言层质量 = 全系统天花板；本阶段只做玩具级，随档案积累逐季增强 |
| 【逐字】**词典定位注记（设计者 2026-09-26 反思，变更 #31）** | 设计者逐字原话：「词典最初只是为了保证语言理解的准确但没想到反而不精确和累赘」——词典定位降级为**冷启动脚手架**：保证最低理解精度用，不作为永久地基；长期路线以语境动态理解为目标（与进阶版动态权重同步演进） |
| 【拍板】**组句：逻辑推演出语句，让它自己会组句，不是背模板对剧本（2026-09-25 变更 #22 拍板）** | **谓语不背专条**：动词在词典里只登记「情态类型 + 论元结构」，组句器做"语义→句法"的**类型级通用装配**（环绕/能力/变化/属性/存在/程度/进行/转变八类，规则属于类型不属于单词）。新动词只标类型，句子自动长出；类型外的关系退回通用组装并声明不熟 |
| 【拍板】**理解：拆句认成分，不是拿整句撞名单（变更 #22 拍板）** | 疑问焦点/否定/条件/祈使的识别全部**词典驱动**——词表从代码迁入词典条目的属性字段，新疑问词/新祈使动词入词典即生效，代码里没有为任何具体词写的专条 |

**词典条目格式**（将来入知识库，v1 存本地种子文件）：
```json
{"词": "查一下", "词性": "动词短语", "释义": "发起查询动作", "拼音/读音": "cha yi xia"}
```

**动词/语法词素条目格式**（变更 #22 扩展，组句与理解的词法知识）：
```json
{"词": "绕转", "词性": "动词", "情态类型": "环绕", "论元": ["主体", "对象"], "释义": "围绕某对象做圆周运动"}
{"词": "怎么", "词性": "疑问词", "疑问焦点": "方式", "释义": "询问方式方法"}
```
- **情态类型**（动词装配类别）：动作 / 变化 / 状态 / 环绕 / 被动 / 存在 / 进行 / 转变——决定谓语怎么组装成句，类型规则通用，不为单词定制。
- **论元**：该动词需要的角色（主体/客体/对象），组句时从规则条件与结论值里填充。
- **疑问焦点**（疑问词属性）：方式 / 条件 / 原因 / 定义 / 确认——理解侧拆句后按此定意图。

## 2. 对话层

| 设计原话 | 工程落地 |
|---|---|
| 【原话】列出从用户指令中拆解出的要处理的事件 | **事件结构模板**（知识库信任区，每种事件类型一套）：`{类型, 主体, 动作, 对象, 时间, 地点, 约束条件}` |
| 【原话】回答用户的问题和执行的任务 | 先对话行为分类（疑问/命令/纠正/闲聊/求助——模式匹配，廉价分流），再进解析 |
| 【隐含】要能追问 | 槽位规则：关键槽缺失→反问；次要槽缺失→带默认假设继续，并声明假设 |
| 【隐含】人会改主意 | 事件生命周期：待办/进行中/完成/已取消；新事件可顶替旧事件，对话记录两者都留 |
| 【原话】上下文和语境 | 指代/省略回填层：解析后把代词绑定到对话记录先行词，绑定置信低→反问 |
| 【拍板】**反问也要组句，不是写死的文案（2026-09-25 变更 #24）** | 缺槽反问/问候回复按槽位描述现场组装（槽名+疑问词+示例），问候回复按时段+在场状态组装；社交句式也是装配产物，不留整句写死的文案 |

## 3. 注意力层（扫描）

| 设计原话 | 工程落地 |
|---|---|
| 【原话】类型权重决定先看谁，权重高的先看到 | **类型注意力权重**（慢变量）：训练得基础值 + 运行时可调（±20% 内、步长 0.02、记 weights.log） |
| 【原话】打分只针对事件本身，和类型无关 | **事件紧急分**（快变量）：每次独立计算 = 严重度 + 截止紧迫度 + 阻塞度；执行顺序只按事件分降序 |
| 【原话】头疼 vs 煤气的例子 | 时间串行注意力（任一时刻深想一件事）+ **三保险**：①预筛急诊通道（浅层模式匹配，全部事件过一遍，命中即插队）②等待老化（每轮未看 +0.1，封顶 +0.5）③紧急打断阈值（事件分越线立即暂停当前工作） |
| 【原话】（见示例）轮得到看 | 有效扫描序 = 类型权重 + 老化增量；任何事件最迟 N 轮内必被看到 |
| 【逐字】**「类型有自己的独立权重也是动态的但是只负责谁先被看见而不影响事情的先后处理顺序和权重打分」（2026-09-26 变更 #31 澄清：两个正交权重体系）** | **体系一：类型可见性权重**——动态可调，只决定扫描序（谁先被看见）；**体系二：事件打分**——只针对事件本身，决定处理先后。两者**正交独立**，互不混入：类型权重再高也不会让事件分变大，事件分再高也不会改变它被看见的次序 |

## 4. 推演层（思考机制）

| 设计原话 | 工程落地 |
|---|---|
| 【原话】将一切视为可计算变量，按情景与约束打权重，计算发生概率 | **因果规则网络**：规则 = `{条件[], 结论, 强度(高/中/低), 出处, 适用范围}`，住知识库信任区/存疑区 |
| 【原话】以逻辑推演为主；生物上以概率计算为主要决策来源 | 结构由逻辑定、强度由统计定；智能体域（动物行为等）概率传播为主，逻辑只搭脚手架 |
| 【原话】概率根据过往经历、环境、心理分析结合大量知识算出来 | 规则强度初值由施工方填常识默认值 → 每次推演输出**带置信标注的预测** → 结果对账 → 强度更新（记 weights.log） |
| 【原话】拆解问题：拆不开就不拆，拆得开就并行 | **原子操作清单**（查知识库/单步演绎/算术/比较/时间换算…十几个）为递归底线；多假设在多 CPU 核并行（符号系统的并行）；GPU 专职神经组件 |
| 【原话】推演即计算，不设阀门 | 确认：推演不受限；输出强制带置信；执行另过白名单（见第 5 节） |
| 【原话】无法计算就答不知道 | 三档概率之外允许输出"未知/需要观察"，观察是合法动作 |
| 【拍板】**规则适用边界：物理规则不能被拦在生物域外（2026-09-25 变更 #23 补账）** | **域拦检**：结论事实带域标签（哪条规则推的就挂哪条规则的域；用户陈述的事实无域=通配）；规则只消费同域或无域的事实，跨域结论不喂给本域规则 |
| 【拍板】**拆得开就并行（变更 #23 补账）** | 正向传播每轮对冻结事实快照**并行求值全部规则**（线程池，规则≥8 条启用），结果按规则序串行落账（竞争假设/置信升级语义不变）；假设分支试算同样并行。诚实记录：v1 是线程级并行，进程级多核开关预留（规则规模上千再启用才有收益） |
| 【原话】**动用一切知识攻坚，直到耗尽方法（变更 #23 补账）** | **试假设法**：条件不足时不只列缺什么——把缺失变量在规则词表里的各候选值逐一分支克隆推演，输出「如果环境潮湿→铁会生锈；如果环境干燥→推不出新结论」式分支报告。分支数设上限（变量≤3、每变量值≤4），防爆 |
| 【拍板】**陌生概念不直接投降（2026-09-25 变更 #25）** | **类比攻坚**：问句里的实体词不认识（分词标未知），但认得它问的目标（如「铜会生锈吗」——铜不认识、生锈有规则）→ 把规则条件里的实体值换成陌生词做类比迁移假设，输出「我不认识铜，假如它和铁同类，规律搬过来就是……——这只是类比，不是知识，需你确认或验证」。类比的产物不是结论，是待验证的假设；确认后可走 REQ 申请新规则。上限 3 条防刷屏 |
| 【拍板】**关系结构也是武器（2026-09-25 变更 #28）** | **结构类比**：同位类比换实体，结构类比搬「关系结构」——问句的目标本身没有规则（如「植物会生病吗」——生病无规则），就在其他域找结构同构的规则：条件数相同 + 结论值的情态归类相同（模态/程度/存在，全部查词典，代码无词表），把槽位映射到问题上（实体槽→问题主体，结论变量→问题目标），输出移植假设与映射表。双重纪律：① 必须明说「这是跨域结构类比，可靠性低于同位类比，只是有根据的猜想方向」；② 产物不进预测存档、不参与对账，确认后才走 REQ。触发次序在同位类比之后（同位无产出才动用），上限 2 条。③ **答非所问优先**：当规则愿单在推的值根本不是用户问的值（问「铁会感冒吗」，愿单在推「生锈」），结构类比先于假设分支作答——愿单的分支结论答的是另一个问题，不许拿来充数。v1 只移植单规则，多规则因果链整体搬家留后期 |
| 【拍板】**从句嵌套 v1（2026-09-25 变更 #28）** | 分句不再只按标点平切：句内关系识别（嵌套深度 ≤1）——分句内部检出条件（如果/要是/当…那么）、因果（因为…所以）、让步（虽然…但是）三类关系（关系标记全部词典驱动，代码无词表），拆成 {关系, 条件部, 主句部}。主句部决定走哪条理解路径；条件部的陈述作为假设事实参与推演（与变更 #23 试假设法衔接：用户亲手给了一支），回答须明示「在你给的条件下」。条件部再含关系标记不再往下拆（深度 ≤1 防爆炸）；更深层嵌套留后期 |
| 【拍板】**语言理解去模板化（2026-09-25 变更 #29，用户举报四连）** | 用户举报属实：①「你是什么」被 search 模板劫持去搜目录——**模板劫持禁令**：带疑问焦点的句子一律先走组合式理解路，「是什么/什么是X」标题检索模板只在话题是纯内容词且无更具体的理解路径时兜底；**自我认知通路**：问句主体指向 AI 自身（你/你的名字/你是谁/你会什么）→ 从自我事实档案作答（名字 INCEPTION、本质=规则推演+知识库的学习系统、能力边界、知识来源），自我事实存 AI 本地不进知识库。②「铁生锈的条件不是氧气加上水才能生锈吗」被剥成垃圾谓词套类比——**纠正识别**：「不是…吗 / …不是X才Y吗」句型 = 用户在质疑规则，不进问答流水线：复述确认纠正内容 → 与现有规则对比 → 差异打成 REQ（modify 候选）交管理员裁决，AI 不擅自改库；**谓词剥取保真**：结构类比的目标谓词剥出后仍含语法词/虚词或超 4 字 → 弃权不出声，宁可没招不输出胡话。③「问铁器附送人不能生存」——**主体锚定相关性**：结论的相关性以问题主体为锚（主句部疑问焦点前的实体词），规则条件值或结论变量须与主体相连，仅共享条件变量不算相关；抽不出主体时退回原公共子串规则。④「碰到水在空气中」认不出——**介词短语事实提取**：「碰到/在/放在/放进+名词（+里/中）」→ 环境接触事实参与推演；分词的连续未登录单字合并为一个词段报生词（不再散字刷屏）。⑤ **措辞词典化**：置信语气四句罐头废止——确定档直陈不挂尾注，其余档位用词典程度副词内嵌句中（很可能/可能/小概率），来源标注缩为（G18）；「按规则推演的结果：」「反向推演结果：」等整句框架废止，单结论直接说话，多结论逐句罗列；缺条件时用提问句收尾（「还缺一个事实：环境是不是潮湿？」），不用固定结束语 |
| 【施工方】**调度传动轴与数据保险（2026-09-26 变更 #30，用户质问审计）** | 用户质问「权重排序是真机制还是摆设」属实：排序只有展示没有执行消费者、outcome 对账只写不读、语境未接入、知识库零备份。本批补建：**① 事件可推进动作+空闲推进**：推演/知识查询类未完成事件是「可推进」的（推进=沿当前规则库试推一遍），每轮答复后按 pick_batch 序取第一件可推进事件推一步（时间串行 K=1），推出结论带置信附上、推不出记缺口（每事件每日限推 1 次防刷屏，推进留痕进思考链）；**② outcome 接回训练**：类型权重训练信号从「只看频率」改为「频率×成功率」——outcome 达成/命中占比高的类型上调、落空多的下调，界与步长不变（±20%、0.02），安全类只升不降不变；**③ 语境加权**：扫描序加语境分——最近 5 轮对话的行为类型与事件同类的 +0.5（量级能翻同档类型的盘，翻不过提醒与安全——时间承诺和安全不被语境盖过），用户状态判「紧迫」时阻塞度加分加倍；**④ 数据保险**：知识库三区+申请+日志与 AI 状态文件（session/suggestions/predictions/weights.log）每日自动快照到 备份\ 目录，保留最近 14 份，快照失败记日志不静默；**⑤ 装配弃权**：组句器对未登记动词/拆不出的变量名不再胡拼兜底——装配失败返回弃权，会话层如实说「这个词我说不好」并入生词学习回路 |
| 【逐字】**「生成的解决方案肯定不是一种而是多种风险表明人来抉择」（2026-09-26 变更 #31 补入）** | **多方案生成**：推演输出从「单结论+置信」扩展为「候选方案集」——每个方案带置信与**风险标注**（可能伤及谁、破坏什么、引发什么连锁后果），并排陈列交人裁决；AI 给方案不给决断，抉择权在人。v1 现状是单结论输出，多方案生成与风险标注**待建** |
| 【逐字】**「每件事情解决的方式过程中带来的影响比如警察击毙了凶手但是凶手家属将凶手视为自己的重要伴侣且心理对凶手的权重远高于对社会和法律和其他生命的地位且心理画像偏激极为极端那就有可能对警察或者是社会造成极大的破坏」「完成任务后可能的发展和暗中失去了什么和得到了什么人们解决问题是往往将对凶手的处置作为主要注意而且往往将完成任务视为解决了这就是明面上可看到的得失和成果但是暗中的解决过程中其他的变化可能带来的发展则是暗中的看不到的得失」（变更 #31 补入）** | **明暗双层得失分析**：推演层产出结论时附带明暗两本账——明面账=任务完成的可见得失与成果，暗中账=解决过程中其他变化可能带来的发展（原话例：凶手家属的报复风险）。对人的分析受第 0 节铁律约束（仅限助手服务目的）。**待建** |
| 【逐字】**「他会根据生物的数据分析来根据心理学等知识来分析人的行为模式和心理画像来判断和基于权重计算的每个行为的可能性同时给出每件事情明面上的得失和暗中的得失」（变更 #31 补入，最终版能力）** | **行为预测与心理画像**：归属最终版（见第 10 节能力三阶段），依赖动态权重机制成熟；受第 0 节铁律约束：危害推演只面向非人对象，对人的建模仅限助手服务目的。**待建** |

**推理方式**：精确计算（有界领域，规则几百条内无压力）+ 双向（观察正向传播 / 目标反向找路径）。

**规则入库（2026-09-22 拍板，变更 #7）**：
- **分类思想**：世界规则一张网，数理生物同库；确定与概率只是每条规则自带的置信属性，不是类别。分区的本质 = 确定性程度（信任区=已证明≈确定性规则，存疑区=能用未证≈概率性规则的天生居所）。
- **知识 ↔ 规则 = 同一条规律的两种形态**：文字形态（给人读的五要素）+ 执行形态（给机器算的 如果-那么）。G 类条目的"用法"字段装执行格式，其余字段装文字内容，一个条目两张脸。
- **G 类条目格式**：`当[条件1;条件2]→则[变量=值]档[高/中/低]域[数学/物理/生物/逻辑/...]`，出处写进条目，适用范围=局限字段。
- **流转**：候选（refine/档案）→ REQ（待审核区，附理由+证明）→ 批准进存疑区（立即可用、带未证明身份）→ 对账累计命中≥3 且命中率≥70% → AI 发移区 REQ → 批准升信任区。全程哈希链，管理员唯一裁决。
- **对账计数**：本地 weights.log（已有）；知识库条目正文只在 REQ 批准后改（守"修改走申请"铁律）。
- **加载**：会话启动从知识库拉 G 类规则；断连/为空时用代码内种子规则兜底（与断连降级同规）。

**经验提炼（2026-09-22 拍板，变更 #8）**：
- **设计者原话**：在使用中**自己发现知识里没人教过的隐藏用法**——如没人教"三乘三是三个三相加"，是 AI 自己在推演过程中发现的。不是计数，不是攒够 500 件再盘点；发现发生在推演干活的过程中，是设计的重要一环。
- **与神经网络的关系**：经验提炼独立于神经网络存在（设计者拍板：不依赖外部 AI，是自己的设计）。神经网络只是将来可选的加速器（模糊规律域），不是前提。低配版纯符号层、全程可审计。
- **工程落地（低配版，brain\discovery.py）**：推演全留痕（档案记录触发的规则链）→ 矿工定期翻档案找规律 → 候选附证据进建议队列 → 人裁决入库。三种矿工：
  - **A 共现**：两条规则经常同次触发 → 可能存在共同上游/隐藏联系，值得人看一眼
  - **B 捷径**：A→B→C 规则链反复出现 → 也许存在直达规律（合并成一条新规则 = 新知识的雏形，附原始链证据）
  - **C 趋同（静态版）**：多条规则指向同一变量 → 可能是同一现象的不同描述
  - **数值趋同（预留）**：两条不同计算路径结果一致（如 3×3 与 3+3+3 都得 9）——需要算术留痕（原子操作清单上线后补）。
  - **E 语词共现（2026-09-25 变更 #24）**：矿工此前只读规则链编号、不读人话。现扫档案 input 原文：规则词表里的概念在对话里反复一起出现（≥3 份档案）→ 候选「这两个概念总是一起出现，也许有隐藏联系」，附证据档案编号，人裁决。
- **阈值（施工方默认值，明文可调）**：共现 ≥3 次、链式捷径 ≥3 次。
